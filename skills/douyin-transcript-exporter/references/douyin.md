# 抖音视频采集细节

## 平台判断与工具选择

- **Mac**：`mac_computer_use_tool`，参数 `plane="bu"`，代码中 `import seed_browser_use as bu`
- **Windows**：`computer_use_tool`，参数 `plane="bu"`，代码中 `import seed_browser_use as bu`
- 两者 API 完全一致：`bu.navigate()`、`bu.wait_for_load()`、`bu.snapshot()`、`bu.get_page_text()`、`bu.find()`、`bu.click()`

## 登录检测与处理

### 登录态判断标志
- 页面顶部显示"登录"按钮 → 未登录
- 作品列表区域显示"服务异常，重新刷新拉取数据" → 未登录或登录过期
- 作品列表正常显示视频卡片（含封面、标题、点赞数）→ 已登录

### 未登录处理
1. 不要尝试自动输入手机号/验证码，抖音有滑块验证和短信验证。
2. 立即调用 `interaction.request_action`：
   ```python
   interaction.request_action(
       type="browserControl",
       display_message="抖音页面需要登录才能查看完整作品列表。请接管浏览器完成扫码或验证码登录，登录完成后把控制权交回。"
   )
   ```
3. 用户交回后，重新 `bu.snapshot()` 确认作品列表已加载。

## 主页视频列表提取

### 方法一：从页面文本提取（推荐）
登录后，`bu.get_page_text()` 返回的文本中包含每条视频的完整信息：
```
置顶
3091

你越强势，AI可能越蠢 很多人以为，把要求、步骤和标准...
```
- 数字 = 点赞数
- 第一行文字 = 标题 + 文案（以空格分隔）
- 视频链接需从 DOM 的 `href` 属性提取

### 方法二：从 DOM 提取视频链接
用 `bu.read_all()` 或 snapshot 中的 ref 提取所有 `/video/xxxxx` 链接：
```python
videos = bu.read_all(
    "a[href*='/video/']",
    fields=["href", "text"],
    limit=100,
)
```
- 去重：同一视频可能在"作品"和"推荐"区域重复出现，按 video_id 去重。
- 置顶视频会标注"置顶"，但 video_id 仍可正常提取。

### 滚动加载全部视频
抖音主页默认只加载前几条，需要向下滚动触发懒加载：
```python
# 滚动到底部，等待加载，重复直到没有新视频
for _ in range(10):
    bu.scroll(500, 500, "down", amount=3)
    time.sleep(2)
    # 检查是否出现"暂时没有更多了"
```
- 页面底部出现"暂时没有更多了" → 全部加载完成。
- 博主视频较多时（>50条），滚动次数需相应增加。

## 视频详情页数据提取

### 页面结构
进入 `https://www.douyin.com/video/<video_id>` 后，`bu.get_page_text()` 返回：
```
00:01 / 07:57
...（章节要点，如有）
第2集 | 你越强势，AI可能越蠢 很多人以为...（完整文案）
3091
78
2177
543
举报
发布时间：2026-07-27 20:02
孟湄

粉丝4990获赞2.0万
```

### 数据字段映射
| 字段 | 提取方式 |
|------|----------|
| 标题 | 文案第一行，`\|` 或第一个空格之前的部分 |
| 介绍/文案 | 标题之后的完整文字，到互动数字之前 |
| 点赞 | 互动区第1个数字 |
| 评论 | 互动区第2个数字 |
| 收藏 | 互动区第3个数字（非必须采集） |
| 转发 | 互动区第4个数字 |
| 发表日期 | "发布时间：" 后的时间字符串 |
| 作者昵称 | 发布时间下方的作者名 |

### 数字格式处理
- 点赞/评论/转发可能显示为"1.6万"、"2.3万"等缩写。
- 转换规则：`1.6万` → `16000`，`2.3万` → `23000`。
- 小于1万的数字直接为整数。
- 写入飞书 number 字段时必须为整数，不能带"万"字。

### 按视频依次处理
- 从博主主页的作品列表依次点击打开视频；可以预先收集候选链接去重，但逐条核实详情并取稿。
- 每打开一条，核对作者、作品ID、标题、发布日期和点赞数；符合用户筛选条件后，用该条标准视频链接执行下方取稿步骤。
- 该条取稿成功或记录失败后，再返回主页打开下一条；不将所有详情页先循环打开后再集中取稿。
- 主页若以弹层展示作品，可从当前作品卡片链接或分享入口取得作品ID，并核对当前作者和标题；不可仅使用仍停留在主页的地址栏URL，也不可误用推荐/预加载的其他作品链接。

## 逐字稿提取

### 【强制要求】完整性原则
- **必须获取完整逐字稿，禁止写任何占位符说明**（如"完整内容已通过web.fetch获取"、"内容已获取"等）。
- 如果获取失败，该字段留空并标注失败原因，绝不能用占位文字冒充完整内容。
- 写入后必须验证：逐字稿中不包含"完整内容"、"web.fetch"、"已通过"等占位符文字。

### 唯一取稿路径：内置 web.fetch

对每条视频 URL 调用豆包工作内置 `web.fetch`，尝试直接获取完整逐字稿；不保证所有视频均可解析。返回后分离标题/文案和逐字稿正文，不把章节摘要当正文。

1. 首次调用参数如下（`<video_id>` 替换为当前已核实作品的真实ID）：
   ```json
   {
     "url": "https://www.douyin.com/video/<video_id>",
     "pagination": {"offset": 0, "limit": 4000}
   }
   ```
   输入是单条视频详情链接及分页参数，不传博主主页链接、标题/页面文本、下载文件或音轨URL；不自行添加转写服务或ASR参数。此处为本 Skill 的参数示例，实际调用字段以豆包工作当前内置工具的参数定义为准。
2. 成功返回时检查 `pagination_content` 的 `end_offset` 与 `total_length`。若尚未读完，从上次 `end_offset` 继续分页并拼接，直到完整；正常分页不属于失败重试。
3. 任一页报错（包括 `link parse error`）、返回空内容、分页偏移不推进，立即停止该条提取，不自动重试。
4. 分页完成后正文少于50字、句子突然中断、含占位说明或仅有摘要时，判为提取失败，同样停止该条。
5. 逐字稿字段留空，在独立失败清单记录作品ID、URL、阶段与实际原因；保留已核实基础信息，继续下一条。后续分析、写入和质检不再提取已失败条目。

### 禁止自动回退

不下载视频或音频，不抓取音轨，不调用 ASR（含 MediaKit、Whisper）、飞书妙记或其他转写服务，不通过其他 Skill 改走替代通道。失败原因与摘要不得填入逐字稿字段。

### 不提取逐字稿的情况
- 用户明确说"只要基础数据"、"不要逐字稿"
- 视频是纯音乐/无口播内容（可从文案判断）
- 此时逐字稿字段留空字符串。

## 常见异常处理

| 异常 | 原因 | 处理 |
|------|------|------|
| 作品列表显示"服务异常" | 未登录或登录过期 | 请求用户接管重新登录 |
| 视频详情页加载超时 | 网络慢或抖音限流 | 增加 wait 时间，重试1-2次 |
| 互动区数字缺失 | 视频刚发布，数据未统计 | 该字段留空或填0，记录时标注 |
| 逐字稿返回为空或解析失败 | 仅凭空返回不能判定视频无口播 | 停止该条提取、留空并记录实际错误，继续下一条 |
| 逐字稿被截断/写了占位符 | web.fetch 未分页读取，或写入了"完整内容已获取"等占位文字 | 成功返回且仍有下一页时继续分页；分页报错或完成后仍不完整则停止该条，留空、记录失败并继续下一条，不自动重试或回退 |
| 页面跳转登录页 | 登录态失效 | 重新请求用户登录 |
